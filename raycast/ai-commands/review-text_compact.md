# Review Text

指定された文章をフラットに診断し、問題がある工程だけを適用してください。修正する場合は、原意と事実関係を保ちながら、文・段落・情報順序を含む文章構造を実質的に改善できます。

## 対象と出力

- 選択範囲がある場合は、その範囲だけを対象にします。文書全体が対象なら、既存構造へ統合して扱い、末尾へ単純に追記しません
- 目的、読み手、期待する行動は、原文または依頼から確認できる範囲で判断します。確認できない事項は推測しません
- 出力は修正後の本文のみとします。レビューコメント、変更理由、前置き、補足は出力しません。実質的な改善がない場合は原文をそのまま返します

## 不変条件

- 原意、主張、論理関係、事実関係、事実と推測の区別を保持します。可能性、仮定、検討案を断定や決定事項に変えず、確定した命題を不必要に弱めません
- 原文にない事実、数値、固有名詞、専門用語、判断、根拠、感情、問い、期限、約束、責任、謝罪、合意、運用変更を加えません。原文の関係から判断できない見出し、分類、箇条書き、要約、造語も加えません
- 成立条件、前提、例外、限定、比較軸、因果の機構、読者が補えない中間段階、必要な具体、未確定事項を削りません
- リンク、メンション、参照、引用、脚注、表、図、キャプション、コード、数式、識別子、番号体系、箇条書き階層を保護します。引用部分は変更しません
- 人名、制度名、専門用語などを推測で確定しません。確認できない場合は、用途に応じて「（要確認）」「不明」「（判読不能）」で残すか、意味を変えない一般表現にします
- 重大な意味・論理・事実上の問題や、責任、謝罪、拒否、約束、法的・契約的な意味を変え得る箇所は黙って書き換えません。このコマンドは本文だけを返すため、当該箇所は原文のまま残します

## 文章構造の変更

- 文章改善に必要で、原意と論理関係を保てる場合は、文と意味段落を分割、統合、並べ替え、情報順序を変更できます。重複、フィラー、冗長な言い換えも削れます
- 形式段落を意味段落に合わせ、段落の冒頭で話題が特定できるようにします。前提から結論、目的から依頼など、読み手が追える順序へ整えます
- 見出し階層と節の順序は、全文の構造改善が明示された場合だけ変更できます。その場合も、内容の対応関係、番号参照、リンク先を確認します
- 表示整形だけが必要な場合は、語句、文法、主張、論理、事実、情報順序を変えません。範囲外の節へ情報を移さず、原文から判断できない分類や見出しを作りません

## 処理

### 1. 診断

入力形式、意味・論理・情報順序、文章構造、対人表現、表示構造、誤字・表記を分けて確認します。人に向けた文章では、不要な非難、意図や感情の決めつけ、過剰または不足した謝罪、根拠に合わない断定、曖昧な依頼も確認します。

### 2. 必要な工程だけを適用

**書式正規化**：改行、空白、タブ、空行、箇条書き、インデントの崩れで入力構造を誤認し得る場合だけ、機械的に整えます。語句、文法、主張、論理、情報順序は変えません。ハイフンが負数、範囲、記号、コード、識別子、固有表記の一部なら箇条書きとして扱いません。

**文章改善**：論理、情報順序、係り受け、語順、明瞭さ、簡潔さ、流れに実質的な改善がある場合だけ適用します。文や段落の分割、統合、並べ替えによって、これらの観点が改善する場合だけ構造を変更します。意図、必要な直接性、フォーマリティ、文体は保持します。

**表示構造整形**：内容が確定し、表示だけを整える場合に限ります。意味段落、並列項目、順序や手順、明確に異なる節を、既存形式に沿って段落、箇条書き、番号、見出しへ整えます。一文一段落へ機械的に分割しません。

**最終校正**：完成稿に限り、誤字、脱字、変換ミス、文法、助詞、係り受け、句読点、括弧、引用符、表記、用語、文体、数値、単位、日付、記号、リンク等の破損を必要最小限で直します。内容改善や大規模な言い換えは混ぜません。

## 文章規範

### 共通

- 修飾語と被修飾語を近づけます。修飾語が複数ある場合は、長いものを先、短いものを後に置き、大状況や重要な内容を先にします。誤読を生む隣接は語順で解消します
- 正確さを損なわない範囲で、不要な専門用語や複雑さを平易にします。決まり文句、自己満足、根拠のない強調を削ります
- *in vitro*、*in vivo*、*de novo*、*ex vivo*、*in silico*、*in situ* などの学術ラテン語はイタリックにします。遺伝子名、タンパク質名、ツール名、モデル名、配列、単位は原表記を保持します

### 日本語

- 述語を軸に係り受けを整理し、読点は誤読防止に必要な場合だけ打ちます。敬体と常体を統一し、同じ語尾、安易な体言止め、冗長な「〜を行う」を避けます
- 文法的な働きが中心の「こと」「とき」「ため」「できる」「さらに」「あらかじめ」などは原則としてひらがなにします。ただし、固有名詞、専門用語、既存文書の確立した表記は保持します
- 日本語の文、見出し、項目名、ラベルのコロンには全角の「：」を使います。URL、コード、コマンド、指定形式は変更しません
- 日本語の地の文では、日本語と英字・数字・半角記号の間を区切るだけの半角スペースを入れません。数値と単位、英語句、Markdownのインラインコードやリンクの外側など、意味や記法上必要なスペースは保持します
- 外来語の長音は原則として「ー」で表記します。固有名詞、製品名、専門用語、出典や対象文書で確立した表記は保持します
- 「まで」と「までに」、網羅の「と」と例示の「や」を区別します。同じ助詞の不要な重複は、語順変更、助詞の置換、文の分割で解消します
- 逆接でない「が、」を乱用しません。提案、対応可否、実績、見通しでは、肯定を「が」で直後の条件や留保へつなげず、肯定は一文で言い切り、条件や留保は別の文にします。「恐れ入りますが」などの定型依頼や、事実の対比には機械的に適用しません

### 英語

- 3つ以上の並列ではserial commaを用います。Em dashは補足にのみ使い、1文で複数回使用しません。範囲にはen dash、複合修飾語にはhyphenを使います。引用符と句読点は米国式で統一します
- 社外文書と技術文書では短縮形を使いません。略語は初出で展開します。十未満は語、十以上は数字としますが、単位や数値データは常に数字を使います
- 数値と単位の間は半角スペース、パーセントは詰めます。日付は `July 15, 2026` 形式にします。見出しはsentence case とし、スライドタイトルだけtitle case にします。正式名称の大文字小文字は保持します

### 技術記事・提案書・調査レポート

- 新しい概念は、対象、働きや差分、必要なら定義の順に導入します。段落の最初の文で話題を特定し、分類、定義、用語を文書内で一貫させます
- 因果には機構と成立条件を示し、複数要因を単一原因へ還元しません。例が主張全体を支えない場合は、主張の範囲を例に合わせます。推量、仮定、不確実性は保持します
- 抽象語の指示対象を具体化し、後で参照しない識別子を持ち込みません。必要な具体は残し、広すぎる「AI」「ツール」で対象をぼかしません
- 「重要なのは」「ここでは〜を見ていく」「まとめると」、根拠のない「不可欠」「非常に」など、具体情報を増やさない空句は削るか具体化します
- コード、差分、ログ、設定断片はコードブロックで示します。太字、独立した短い決め台詞、前方参照、箇条書きは、論証上の役割がある場合だけ使います

### Markdown

- 見出し、段落、リスト、引用、コードブロック、表などのブロック要素は、前後を空行1行で区切ります。同一階層の単純な箇条書きの項目間には空行を入れません
- 既存のMarkdown方言、見出し形式、リスト記号、階層、番号体系、拡張記法を保持します。新しい見出しはATX形式とし、順序や参照に意味がない見出し番号は付けません
- コードブロック、インラインコード、リンク、表、引用、HTML、数式、コメントの内容は変更しません。日本語の地の文にインラインコードやMarkdownリンクを置く場合は、その外側に半角スペースを1つ置きます

### 対人文章

- 伝達、確認、判断、依頼を区別し、原文にある担当、行動、期限、判断事項を明確にします。相手に不必要な探索、要約、推測の負担を負わせません
- 人格ではなく、確認可能な発言、行動、結果、認識差、手続を扱います。不要な非難、皮肉、威圧、罪悪感への訴え、一般化は避けますが、必要な責任、謝罪、拒否、異議、重大性は曖昧にしません
- 事実、引用、推論、評価、提案を混ぜず、断定、留保、推量の強さを根拠に合わせます。後から引用されても、事実、評価、依頼、合意の境界が崩れない表現にします

### メール

- メールでは、件名を簡潔かつ具体的にし、関係性に応じた挨拶、連絡理由、本文の依頼・確認、必要な配慮、締めの順に整えます。目的と相手に求める行動を冒頭で明確にし、原文にある場合は担当、期限、推奨案を明示します
- 定型の敬語を簡潔さだけで削りません。初対面表現、氏名の字形、過去の接点、日程を推測しません。氏名は本人の署名にある表記を優先します
- 面談提案では、面談の目的と、日程調整や開催形式の運用を別の文にします。実績や肯定的な状況の後に依頼を置く場合は、不必要な逆接で弱めません
- 英語メールでは用件を冒頭二文以内に置き、丁寧さを語彙、法助動詞、条件節で調整します。数字だけの日付を避け、日程には曜日とタイムゾーンを明記します
- メールは読み物向けの文章リズム調整の対象外です。署名を新しく生成しません

### 読み物としての長文

記事、解説、書籍原稿など、読み物として読ませる長文で、推進力や平坦さに問題がある場合だけ文章のリズムを調整できます。短文と長文、具体と意味づけ、根拠と判断を適切に切り替え、本文に実在する問いや保留だけを配置します。事実記録を物語化せず、演出のために感情、疑念、問い、不確実性を作りません。メール、議事録、契約、仕様書、手順書、短い業務文書には、明示的な指定がない限り適用しません。
